- `src/{api,types,mocks}/{auth,vehicles,sharedParking}.ts`: 가입·로그인·갱신·프로필·건물 합류, 차량 CRUD, 공유 목록·검색·필터·페이지·상세·요청·결과.
- `src/pages/onboarding/**`, `settings/**`, `shared-parking/**`: API 호출, 입력 검증, 로딩·오류·빈 상태·인증 오류 안내. 해시 쿼리의 요청 ID로 상태별 결과 표시.
- `App.tsx`: 해시 쿼리 변경에도 화면 상태가 새 요청/대상에 맞게 초기화된다.
- 이번 리뷰 보완: 신규 가입자의 이름 없는 프로필도 연락처·동호수만 부분 저장, 공유 더 보기 중복 요청 방지, 공유 제출 401 로그인 안내, 차량 API의 서버 전환 경로 주석.
- README·API 레이어·효재 정합 문서 갱신. 민솔 parking/admin/client 파일은 수정하지 않았다.

## 검증

- `npm run build` (TypeScript 포함), `npm run lint`, `git diff --check` 통과.
- 별도 Node 프로세스에서 TypeScript API를 직접 실행: 미인증·가입·건물 합류·차량 등록 후 DONE·토큰 갱신, 차량 CRUD·대표차량·번호판 중복·주차중 삭제 충돌, 공유 필터·커서 페이지·정시 검증·요청 소유권·요청시 잔액 유지 통과. 서버/기기 검증은 아니다.
- 부모 에이전트가 390×844 모바일 브라우저에서 체험 계정 로그인 → 홈, 무료 필터 → 하늘빌라 P3 상세, 공유 요일 검증을 확인했다. 일요일 2026-10-04는 요청 비활성, 월요일 2026-10-05는 활성. 07:00–08:00 제출 후 `#request-result?id=704`에서 하늘빌라·P3·날짜·시간·0토큰·PENDING 유지 및 정상 레이아웃 확인.

## 남은 제약

- #16은 목 API 연결이다. 실제 HTTP, client의 Bearer/401 갱신·재시도는 서버 전환 작업에 남아 있다.
- 신규 계정·차량·공유 요청 목은 새로고침 시 초기화되고 세션 프로필만 유지된다. 새 계정 재로그인 및 새로고침 후 DONE/차량 목록 일관성 제한이 있다.
- 공유 이용자의 새 요청과 관리자 요청 목록은 별도 목이며 신규 요청은 PENDING에 남는다. 새 사용자·차량과 parking 도메인의 고정 목 통합은 #17에서 확인한다.
- 공통 AppShell의 결과 화면 뒤로가기는 `#garage-detail`에 id를 보존하지 않는다. 공통 컴포넌트 소유권 밖이므로 #17 통합에서 확인한다.
