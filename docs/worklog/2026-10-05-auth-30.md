# #30 인증 API 연결 — 효재 트랙

## 범위
- PR #31이 반영된 `4ad3ff3`에서 시작. 사용자 요청에 따라 관리자 에이전트와 함께 `src/api/auth.ts` 구현·검토.
- 배포 명세의 AuthTokens, UserMe, refresh 응답 및 최신 #30 댓글 기준. 함수 이름·타입과 기존 목 코드를 유지.

## 변경
- 서버 모드: login/signup은 `auth:false`로 요청 후 토큰을 `chagok.auth`에 저장하고 `/users/me`로 프로필·건물 ID 준비. 프로필 조회 실패 시 부분 로그인 세션 삭제.
- refresh는 `auth:false`로 새 토큰 두 개를 받아 저장. 동시 갱신은 Promise 공유, 실패 시 세션 삭제. 로그아웃·새 로그인 후 도착한 이전 갱신은 새 세션을 덮지 않음.
- getMe/updateMe/joinBuilding 실제 분기와 프로필·건물 캐시 갱신 추가. 서버 토큰에는 목 만료 시각을 적용하지 않고 HTTP 401을 사용.
- 목과 서버 세션 형식 구분. 기존 목 로그인·프로필·갱신과 getMockUserId 인터페이스 유지.

## 검증
- `npm run build`(tsc 포함), `npm run lint`, `git diff --check` 통과.
- 임시 Node VM + 가짜 fetch 통합 검사 12개 통과: 로그인/프로필/Bearer/비밀번호 미저장, 재로드 복원, 프로필 수정, 건물 합류, 가입, 모드 분리, 동시 401 한 번 갱신과 재시도, 갱신 거부 및 원래 401 전달, 초기 프로필 조회 실패, 잘못된 토큰 응답, 이전 갱신의 새 로그인 덮어쓰기 방지, 기존 목 회귀.
- 관리자 에이전트 검토: 차단 결함 없음. Vite의 auth 동적 import chunk 분할 안내는 정적 import도 있기 때문이며 빌드는 성공.

## 남은 작업
- backend #36의 test 서버 주소·CORS·계정/시드 응답 후 실제 서버 QA. 이번 검증은 실제 서버 접속 검증이 아님.
- 목/서버 모드 변경 시 해당 모드로 다시 로그인. 목 삭제는 #30 6단계.

## 추가: 차량·공유 주차 서버 분기 (#30 4단계)
- 사용자 후속 요청으로 `vehicles.ts` 4개, `sharedParking.ts` 5개 함수에 서버 분기 완료. auth 6개와 합쳐 효재 담당 15개 함수에 실제 호출 경로가 생김.
- 서버 모드에서 각 함수는 공통 request로 즉시 반환해 목 ID 조회·검증·데이터 변경을 실행하지 않음. 기존 함수 시그니처와 목 코드는 유지.
- listGarages는 명세의 위치·검색·필터·페이지 쿼리를 전달. 차량 삭제 204와 서버의 비즈니스 에러도 공통 client 처리 사용.
- 빌드·린트·diff 검사 및 가짜 fetch 통합 검사 14개 통과: 9개 함수 HTTP 계약, 서버 ID와 상태, 검색/커서 인코딩과 좌표, 빈 쿼리 생략, 204, Bearer, 에러 전달, 기존 목 차량 CRUD 및 공유 요청 흐름. 앞선 인증 12개와 별도로 검증.
- 실제 관리자 승인과 토큰 정산 검증은 test 서버 연결 후 진행. 이 단계는 서버 호출 코드 구현 완료이며 실제 서버 전체 흐름 검증 완료를 뜻하지 않음.
- 관리자 검토: 메서드·경로·요청 형태 일치. 서버 차량 등록 직후 캐시의 onboarding_step은 다음 getMe에서 갱신된다. 현재 차량 등록 화면은 바로 home으로 이동하며 이 캐시로 라우트를 막는 코드가 없어 추가 조회로 등록 성공을 실패 처리하지 않는다.
